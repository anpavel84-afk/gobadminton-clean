## Обязательная композиция

- Светлый BottomSheet поверх сохраняющейся карты, handle сверху, закрытие справа поверх фото.
- Крупное фото примерно4:3 с округлёнными углами. Реальная галерея показывает фактический индекс/число снимков; при единственном фото фиктивного счётчика нет.
- Название площадки, справа компактный лаймовый рейтинг только при наличии подтверждённых данных и определённой семантики рейтинга.
- Адрес и дополнительная строка местоположения с иконками. Не дублировать один адрес ради второй строки.
- Светлые компактные плитки характеристик: число кортов, парковка, раздевалки/душ. Только реальные явно заданные сведения; неизвестное не означает отсутствие.
- Заголовок «Контакты площадки». Телефон и сайт — отдельные широкие контурные строки с иконками, Telegram/WhatsApp — две кнопки рядом при наличии ссылок. На узкой ширине корректный перенос. Сайт показывает читаемый домен. Ссылки/телефон безопасно нормализованы; внешние ссылки защищены.
- Яркая широкая кнопка «Показать игры на этой площадке» со стрелкой. Для достоверно пустого расписания — создание игры в том же попапе.
- Иконки и типографика из существующего Style Guide, без emoji и нового визуального языка. Поля/отступы, радиусы и иерархия приближены к эталону; 390/430px и desktop без горизонтального скролла.

## Данные и ограничения

Демонстрационные значения4,8 /1/4 /6кортов /телефон и домен из картинки не являются данными площадки и не публикуются. iOS Photos overlays (Monday17:33, back, ellipsis, share, heart, info, sliders, trash, Live Text) не являются частью дизайна сайта.

У Demo Hall Presnya публичный DEV API подтвердил publicContacts:null. Показать одну спокойную подпись «Контакты пока не добавлены», убрать техническую строку «Публичные контакты организации». Не раскрывать частные contactPhone/bookingNote.

Существующий API даёт publicContacts и одну cover; галерея/характеристики/рейтинг не должны выдумываться во frontend. Недостающие поля и управление ими уточняются в существующем блоке V1a/V3b, реальное заполнение — V2; не создавать дубли этого бэклога. Рейтинг требует определённого источника и расчёта, он не возникает из рейтинга игроков/тренеров.

## Связанные три исправления

1. В расписании площадки использовать GameCover: изображение игры → площадки → штатная заглушка, отдельно от Avatar организатора.
2. Контакты оформить по этому макету, сохранить безопасность и честное пустое состояние.
3. Создание игры из карты встроить в попап с выбранной площадкой, общими validation/CSRF/publish/unknown-result механизмами, возвратом к площадке и сохранением карты/камеры. Обычная страница создания сохраняется.
