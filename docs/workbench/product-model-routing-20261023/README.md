Astra High — отдельный эксперт **после нового содержательного QA/CI FAIL** для любого профиля. Она не пишет исправление и не принимает его. Один пригодный диагноз на тот же SHA/findings повторно не вызывается. Infrastructure/auth/quota/transport/unknown не маскируются под source FAIL. QA не подменяется Астрой по умолчанию.

## 5. Процессы и экономия

PMA управляет; технический PM не превращается во второго scheduler. Для готовых карточек этого пакета **не требуется ещё один платный planner только для повторного выбора модели**. Если current source выявляет новый contract gap — один адресный Sol Medium/High либо Astra High по реальному риску.

Авторские проверки, сборка, CI, импорт, выпуск, smoke и watchdog — детерминированные действия, не отдельные LLM. Независимая QA — один предметный review exact candidate; после исправления — проверка findings и затронутых рисков. Уже выполненные sandbox/login/canary не повторяются без изменения соответствующей границы.

Цикл: Cursor → реальные проверки → Antigravity QA → при содержательном FAIL Astra brief → Cursor repair → свежая QA/CI → DEV ACCEPTED. Дорогая Astra не становится обычным QA каждой формы. Не выдумывать деньги/токены/внутреннюю модель Cursor Auto.

## 6. Параллельность и готовая последовательность без новой очереди

Это **предложение очередности для применения текущих приоритетов**, не изменение Project. Сначала действующий PMA завершает #225/#226 и квалификацию Cursor, затем Antigravity и #218. Этот пакет не меняет их работу.

После сквозной приёмки команды: подготовка библиотеки обложек (read-only исследования) может идти независимо от узкого map/UI остатка; загрузку контента выполняет отдельный разрешённый оператор. #177/M2R, #156 и #184 пересекаются по карте/попапам — один writer и актуальные locks. #207 не запускается, пока UNKNOWN не разрешён. V2 зависит от админского read/write; FR-3 UI зависит от принятого API. PG API/DDL этапы сериализуются по migrations/OpenAPI; UI отделяется после замороженного контракта.

`lock_groups` в JSON — рекомендации для сопоставления с существующими ресурсами, не новое имя machine-lock и не право менять активную блокировку. Два разных Issue не означают независимые файлы. Runtime locks остаются обязательными.
