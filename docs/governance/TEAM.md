# Роли GoBadminton CLEAN

Полномочия и разделение ответственности находятся в разделе 3 [единого регламента](../rules/ENGINEERING_OPERATING_MODEL.md). Этот файл — указатель, не второй орган управления.

Owner — Павел; PMA — единственный оперативный координатор; Advisor — независимый советник. Технический PM предлагает план и exact маршруты по коду/риску; PMA проверяет их в пределах принятой делегации; действующий router исполняет только допустимый набор. Автор, независимая QA и OPS имеют разные эффекты и доказательства результата.

Product/UX, Architect, Design, Content и профильные reviewers подключаются по необходимости. Название роли в чате не создаёт отдельную identity, доступ, QA independence или разрешение расхода.

Прямое поручение Owner специалисту сохраняется в точной области; перед эффектами согласовать ownership, чтобы не появился второй writer. Backlog/приоритеты — GitHub Issues/Projects, execution facts — Actions и receipts. Отдельный Hub/дублирующий task board не требуется.
