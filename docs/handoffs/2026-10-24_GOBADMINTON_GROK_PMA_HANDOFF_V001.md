## 1. Цель продукта
GoBadminton — независимая от BadmintonOpen платформа для поиска, создания и проведения игр в бадминтон: игры, площадки, тренеры, друзья, сообщения, заявки, участие, завершение и обратная связь. Важны реальные ограничения мест, серверная атомарность и privacy: заявка ≠ подтверждение ≠ участие ≠ посещение ≠ состоявшаяся игра.
Stack: TypeScript monorepo; NestJS/Fastify API, PostgreSQL+PostGIS, Next.js Web, отдельный admin, React Native/Expo как долгосрочный mobile target. PROD Москва Web + Германия API/DB/worker; DEV изолирован на Германии. [Style Guide First](../decisions/OWNER_DECISION_FRONTEND_STYLE_GUIDE_FIRST_V001.md) обязателен для UI, кроме записанного OWNER_VISUAL_OVERRIDE.

## 10. Критерии любой приёмки и ошибки
- **CI PASS ≠ independent QA PASS ≠ installed ≠ model READY ≠ DEV ACCEPTED ≠ OWNER ACCEPTED ≠ PROD.**

- При substantive QA/CI FAIL — отдельный Astra diagnosis и bounded repair, не random author retries. При infra/transport/quota — separate preflight/reconcile, не выдумывать source defect.

- Пользовательские интерфейсы проходят Style Guide parity, mobile/accessibility и реальные неразрушающие DEV smoke; исходные требования не урезать ради CI.
- При отсутствии GitHub Projects/источника/приватной metadata отмечать `NOT_VERIFIED`, а не «сделано».
