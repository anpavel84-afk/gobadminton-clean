# Пользовательские сценарии и ошибки

Статус: **PROPOSED_PRODUCT**, технические ограничения — из domain model.

## Игрок

Открывает выдачу без регистрации → выбирает город/дату/уровень → читает время, площадку, формат, доступные места, стоимость/условия и организатора → нажимает «Оставить заявку» → проходит VK/Яндекс → возвращается к той же игре → проверяет минимальный профиль/уровень → подтверждает отправку → видит pending, а не обещание места.

После confirm показывает место и условия; после reject — понятный отказ без раскрытия чужих данных. После отмены игры показывает cancelled и явное отсутствие автоматического возврата платформой. Если игрок переходит с invite link после входа, контекст ссылки восстанавливается, но return URL остаётся allowlisted local path.

Нет аккаунта провайдера / провайдер недоступен: другой разрешённый способ входа; недопустимо скрыто включать password/SMS. Нет двух разрешённых провайдеров — временная невозможность отправить заявку, каталог продолжает работать. Logout не отменяет участие.

## Организатор

Проходит разрешённое onboarding-подключение → создаёт organizer context → выбирает существующую площадку → задаёт конкретное время/уровень/формат/capacity и уже занятые вне сервиса места → задаёт внешний контакт/условия → preview → publish → share link → список заявок → confirm/reject.

При одновременной работе двух менеджеров последний слот получает только одна заявка. Второй экран получает conflict, перечитывает состояние и не маскирует ошибку как success. Отмена обязательна с объяснением; статус и список участников изменяются атомарно. После окончания организатор отмечает состоялась ли игра и посещение, неизвестное не заменяется на «да».

## Личный кабинет

Минимум: собственные текущие/прошедшие заявки, привязанные способы входа, минимальный профиль, logout/revoke sessions и удаление аккаунта по регламенту. Удаление owner-аккаунта не должно оставлять действующий Organizer без владельца: transfer/close выбранной процедурой.

## Обязательные состояния UI

Loading; empty; API unavailable; unauthenticated; forbidden; outdated version; no seats; application closed; pending; confirmed; rejected; withdrawn; cancelled; expired. Отдельные тексты для «запрос отправлен» и «место подтверждено». Кнопка disable не является серверной проверкой.

Offline допускает чтение ограниченного кеша с пометкой времени. Отправку заявки, подтверждение и изменение capacity офлайн не ставим в скрытую очередь: пользователь должен понимать, что действие ещё не выполнено.

## Продуктовые развилки

Точная шкала уровня, допустимые форматы, минимальный профиль и канал срочных уведомлений уточняются с пилотными организаторами, не выводятся из старого сайта. [Open decisions](../manifest/OPEN_DECISIONS.md).

## Утверждённое продолжение после встречи

Мои игры → Управляю → игра → Участники / Итоги: до игры заявки, во время быстрый present, после — held/not_held/later и необязательное уточнение unknown. Игрок в собственной истории видит assertion/автора, может agree/disagree, оставить private contextual feedback или report даже без доступа к чату. Менеджер не цензурирует отзыв отметкой absent. Личная заметка явно «Видно только вам». Один reply, optional explicit next-game invitation.
