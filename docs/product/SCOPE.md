# Продуктовый scope и этапы

Основание: [презентация](../reference/PRESENTATION_BRIEF.md) и [Owner decisions](../manifest/OWNER_DECISIONS.md). Ниже — **PROPOSED_PRODUCT** baseline для дальнейшей детализации, кроме явно подтверждённых границ.

## Первый вертикальный MVP

Игрок открывает публичную выдачу по городу/времени/уровню, видит карточку конкретной игры, входит через VK или Яндекс, оставляет заявку и получает решение организатора. Организатор создаёт и публикует игру, учитывает свободные места, делится ссылкой, подтверждает/отклоняет заявки и отменяет игру при необходимости. Игрок видит свои заявки, может отозвать участие до начала. Результат игры и посещения фиксируются отдельно.

Минимально необходимы: безопасный аккаунт, scoped organizer, каталог площадок, game lifecycle, availability, share link, собственный список заявок, управление заявками и audit. Это необходимая поддержка шести основных возможностей презентации, не приглашение строить большую социальную сеть.

## Матрица этапов

| Возможность | MVP / пилот | Следующие этапы |
|---|---|---|
| Москва и русский UI | Да | Другие города, языки и региональные политики |
| VK / Яндекс | Да | MAX, Сбер, Apple/Google и иные adapters после решения |
| Web | Первый предлагаемый delivery target | Сохранится полноценным клиентом |
| iOS / Android | Общая архитектура и mobile compatibility с первого API | Исполняемые clients после первого API/web-среза; сроки не обещаны |
| Заявка → подтверждение | Да | Instant booking как явная game policy |
| Отмена/withdraw | Да, без расчёта возврата | Детализированные cancellation rules |
| Уровень | Self-declared с понятным обозначением | Верификация тренером, отдельный рейтинг при доказанной потребности |
| Игры по ссылке | Да | Реальные private groups только с ACL |
| Площадки | Небольшой curated catalog | Предложения/дедупликация/интеграции |
| Карта | Координаты и ссылка в навигацию | Собственная стилизация без зависимости домена от map SDK |
| Уведомления | Внутренние статусы/список заявок, операционный канал пилота | Push/email adapters по принятому delivery-срезу |
| Платежи | Нет, только внешние условия | Финансовый контур, не boolean-поле |
| Команды организаторов | Membership-модель | Staff UI и расширенные роли |
| Повторяющиеся игры | Не обязательно | Series → независимые instances |
| Очередь ожидания, чат, пакеты, клубные imports | Нет | Отдельная проверка продукта и ADR |

## Что не включаем автоматически

Бронирование корта, CRM/ERP клуба, массовый импорт расписаний, турниры как полноценный спортивный движок, внутренний мессенджер, рейтинговый алгоритм, социальная лента, рекламная сеть, мультиспорт и сбор денег не являются обязательствами MVP.

Цель — не запретить рост, а не реализовать будущие гипотезы вместо первой полезной петли. Для каждой новой возможности нужно: подтверждённый сценарий → семантика → зависимости → контракт → acceptance → rollout.

## Definition of usable pilot

Есть реальные разрешённые организаторы и карточки, реальные VK/Яндекс end-to-end, понятные правила участия, учёт заявок/исходов, privacy/terms, поддержка, восстановление после сбоя и пройденный независимый QA critical flows. Ни skeleton UI, ни build PASS, ни заполненные документы отдельно этого не доказывают.
