## A integration and publication semantics

### Candidate preparation

Add typed text surfaces and a resource-specific candidate builder in the owning service. A candidate contains exact normalized-to-storage field values, target entity identity/generation, expected resource version, actor and the policy version. Use the existing input trim/length validation. Keep profanity-normalized text separate from the stored/provider text. Never rewrite a submitted name, address, quote or criticism to make a check pass.

Use a shared text batch adapter for one resource mutation, with stable field indexes and explicit result-count validation. OpenAI text batch input permits separate text items, so retain per-field results and category evidence. Limit candidates to the actual supported DTO lengths and a small fixed maximum number of fields. A game contains at most title, host name, host contact, trainer snapshot, training description and settlement terms. Do not concatenate unrelated actors' content into one classifier item. A single resource preflight has a total deadline of 6 seconds, including the existing maximum one retry. Reserve the existing `text` budget before every actual request. Share bounded provider concurrency with image processing so adding text cannot create unbounded parallel calls.

Sequence for each public mutation follows these steps.

1. Parse input and form the existing idempotency request hash. Obtain authorized replay first. An accepted replay needs no new classifier call.
2. Read and authorize the target with a short preflight. Check expected version and current actor/session/permissions before external processing. Capture stored fields needed for merge or publication. End the transaction before network I/O.
3. Check changed public fields, or the complete text snapshot at first public exposure. Run local policy, then contextual provider policy. An unchanged field with exact matching evidence under the same model/local policy/provider policy reuses its evidence.
4. Run the existing idempotent transaction. Repeat actor/session/capability/ownership checks and existing domain locks. Compare the current resource version, identity/generation and relevant stored fields with preflight. Derive the committed candidate again from that locked state. Verify exact fingerprints against prepared evidence.
5. Write content and approval bindings atomically. Existing domain event/outbox/push generation occurs only after the accepted content write inside the same transaction. A stale prepared candidate returns the existing conflict response. An already committed same-key winner takes replay precedence.

Resource versions can change for unrelated reasons. Compare the full existing version first because current callers already rely on it. Reuse content evidence when rebuilding a new candidate after a legitimate conflict, without pretending the old publication binding applies to the new version. Do not repeatedly run external work from within MutationRunner technical transaction retries.

For concurrent identical preflights, a process-local bounded single-flight keyed by policy/surface/fingerprint may avoid duplicate requests. Cross-process correctness comes from rate-budget reservation, existing idempotency and publication CAS. A distributed job claim system is unnecessary for A. An ambiguous provider timeout creates a retryable failure with no public content change. An ambiguous database commit is reconciled by the existing receipt path.

Both OAuth and email authentication already call the shared default helper. Regression-test their public-profile result via those normal entry points with synthetic identities. ## Text policy and error contract

Define `public-text-v1` and `ru-profanity-v1` as separately versioned policies. HMAC exact storage text with the existing moderation fingerprint secret and a text-specific domain prefix, surface and fingerprint version. Cache identity includes surface, fingerprint, policy, local policy, provider and immutable model. Image fingerprint inputs and image policy remain byte-for-byte compatible.

The local layer uses Unicode normalization, case folding, ё→е, a bounded Cyrillic/Latin confusable map, practical transliteration variants, basic digit substitutions and separated-letter reconstruction within a bounded token window. Match curated complete tokens and explicitly enumerated inflections. Never flatten all whitespace across a document or match arbitrary substrings. Include legitimate Russian and international names, place names, surnames and badminton terminology in regression fixtures. Use contextual exceptions carefully. No universal personal-name allowlist can replace token boundaries.

Short identity/title fields apply deterministic rejection for high-confidence obscenity tokens. Prose checks record local signals and use contextual classification. Quoted words, reports of abuse, negative reviews and sports criticism require contextual handling. In existing review surfaces, ambiguous local/provider results remain in the actual human queue. A plain negative sentiment is allowed. Provider category scores never become public ratings, reputation or account punishment.

Extend the adapter with the documented text-category booleans including harassment, harassment/threatening, hate, hate/threatening, illicit, illicit/violent, self-harm, self-harm/intent, self-harm/instructions, sexual, sexual/minors, violence and violence/graphic. Validate the current pinned model response, result count, required booleans and applied-input metadata according to the official schema. Keep text validation independent from the six supported image categories. A missing/incompatible response produces temporary unavailability. Policy decisions use category booleans, without invented confidence thresholds.

| Outcome | API/UX rule |
| --- | --- |
| ALLOW | Normal existing success response after atomic publication. Evidence remains server-side. |
| REJECT | HTTP 422 `PUBLIC_TEXT_CONTENT_REJECTED`, bounded field identifiers and neutral Russian correction text. Keep prior public content and the user's unsent form. Do not expose matched token, raw provider category response or confidence scores. |
| PENDING_REVIEW | Existing review receipt with its real pending status and immutable revision/receipt token. Public tip remains the previous approved revision. Use only when an actual intake was persisted. Profiles, games and comments have no new automatic pending workflow in A/B minimum. |
| TEMPORARILY_UNAVAILABLE | HTTP 503 `MODERATION_TEMPORARILY_UNAVAILABLE`, retryable and old content retained. Schema/policy mismatch can keep existing `MODERATION_POLICY_MISMATCH` internally with the same safe UX. |
| Budget exhaustion | HTTP 429 `MODERATION_RATE_LIMITED`, bounded Retry-After. Avoid image-specific wording for text. |
| Stale candidate or revoked actor | Existing 409/403/404 semantics, preserving privacy and domain contracts. No provider approval bypasses these checks. |

Document these responses on each affected operation in `packages/contracts/openapi.json`, regenerate only affected generated contracts through existing scripts, and add a small typed moderation-error representation if clients need field lists. Native clients receive identical server enforcement. Preserve success shapes where possible. Reuse the current API client's problem parsing. Profile, trainer, game and organizer forms must display correction or retry guidance and keep submitted input without optimistic public replacement.
