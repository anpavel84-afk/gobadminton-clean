# ADR-0011 — Unified Players Radar source candidate

Status: **PROPOSED_IMPLEMENTATION / PENDING_INDEPENDENT_QA_AND_PM_SOURCE_ACCEPTANCE**. Date:2026-10-08.
Implements the [independently reviewed ADR-RADAR-006](https://github.com/anpavel84-afk/gobadminton/blob/6134a80a6a636d02c1bdb47b75e7c5a24b034ad0/docs/workbench/architecture/radar-unified-distance-20261008/ADR-RADAR-006-unified-distance-directory.md) under the exact admitted unified API assignment. No product decision or release authority is added.

Full filtered D∪P belongs to one PostgreSQL/PostGIS read projection, independently of publisher consent lifecycle. G1 endpoints stay policy/model isolated. V2 uses additive consent and100m/1km current ephemeral metadata; old publication is not upgraded. HTTP clients receive approximate numeric distance and current permitted projections, never raw GPS or private source accuracy.

Implementation selects a **global non-geographic revision** rather than initially partitioning counters by region/namespace. Every eligible-set/projection/order dependency advances the epoch transactionally through a DEFERRABLE INITIALLY DEFERRED row constraint trigger at commit, coalesced once per transaction, including profile/intent/trainer, account/session authority, bilateral blocks, presence/consent, avatar provider and conversation/contact projection changes. Session last_seen telemetry is excluded. This is stricter invalidation than the reviewed regional revision vector and preserves its consistency guarantee across all scopes. It stores neither per-user movement nor query allocation/history.

The REPEATABLE READ query binds rows/counts/deadlines to one snapshot; its final revision FOR SHARE is a visibility fence covering the entire union, including unreturned members. Writers cannot commit an affecting change across that fence. Deferred revision bumps run after domain writes have completed; no domain lock acquisition follows the counter lock. Immediate revision triggers would invert the established contact/presence versus revoke/session/account lock order and are forbidden. Own TRUNCATE/reset advances after acquiring its relation lock; normal row writes use deferred triggers. A change since the snapshot produces serialization failure/stale409. Queries acquire actor/session before budget rows, read projections without target row locks, then acquire the revision fence last and hold it through commit. They never acquire target/profile/presence locks after the revision fence, avoiding an inversion with eligibility writers that hold those rows before their transactional trigger. Preview/contact retain established pair-before-sorted-presence fences and final wall-clock eligibility; they do not depend on a global revision equality changed by their own conversation creation.

Consequences: false-positive stale contexts and global write serialization are accepted conservative costs for this bounded source candidate, measured with10k profiles/1k publishers. Region/namespace partitioning can follow only as separately reviewed optimization preserving all dependencies and lock order. Context refresh never silently mixes pages. Source model migration is0022; all applied migrations remain unchanged. Encrypted purpose-specific token keys derive from server pepper and coordinated restore epoch, keeping private origin out of cleartext cursors. Capability switches default off; rollback retires v2 generations and rotates tokens before older code runs. No frontend, asset, public real-data or installed runtime changes belong here.
