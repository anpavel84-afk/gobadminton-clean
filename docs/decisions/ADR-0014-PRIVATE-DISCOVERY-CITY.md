# ADR-0014 — private discovery city and safe bootstrap hint

Status: READY_FOR_REVIEW implementation source selection, 2026-10-09. Code acceptance remains independent QA. Authority: [P2 assignment](https://github.com/anpavel84-afk/gobadminton/blob/c07deefa68cd3c8ed95cf900130a0a7a5979df97/docs/prompts/implementation/product-api-discovery-preferences-20261009-v001.md), base `5573212efa5ae3d3c42cea208b45d98a5c5be15b`; [PM disposition](https://github.com/anpavel84-afk/gobadminton/blob/b5b4296c4cbea15f917722297f7da60ca2a1bd75/docs/operations/PRODUCT_DELIVERY_REBASE_20261009_V001.md). SOURCE_ONLY; no runtime/release authority.

Context: ordinary discovery needs a nonblocking default city and a persistent explicit account choice. SocialProfile.cityId affects public directory eligibility; Radar carries separate consent/location. Neither resource expresses a private discovery choice. The [reviewed city contract](https://github.com/anpavel84-afk/gobadminton/blob/4e7cfad2c6054e9a3c9480d2348763cb1cc9bdcd/docs/workbench/architecture/fb01-review-city-v001/README.md) has [independent review](https://github.com/anpavel84-afk/gobadminton/blob/300a4982d7295363c9bf24b00cf7f92c1e0f6705/docs/workbench/qa/qa-fb01-review-city-v001/README.md); P2 implements its API/storage portion only.

Decision: Profiles owns `user_discovery_preferences`, one row per internal User, independent of profile completion. Migration 0024 adds an empty table with user/city FKs, the two canonical region UUIDs and a positive integer version. GET returns null/version 0 without a row. PUT requires supported cityId and expectedVersion, rejects all extra fields, and uses the established cookie session, Origin, CSRF, actor/session fence and scoped insert-first idempotency transaction. Native bearer-only consumer mutation is not implemented by the existing runtime; this additive route does not invent a second transport. The published OpenAPI documents cookie security accurately.

First write inserts conditionally at version 0; subsequent writes use a version predicate and increment exactly once. Same-city explicit saves still increment. Competing first writes return one success and one VERSION_CONFLICT; same-key repeats return the original receipt after current authorization, without restoring an older city. The shared actor fence serializes writes with account retirement. Maximum version 2147483647 matches project practice; exhausted versions return a conflict rather than SQL overflow.

Identity deletion_pending clears the city, retains an incremented version tombstone and deletes this operation's receipts, since their response bodies also contain the private choice. Cancellation of deletion cannot replay an old version-0 write. Hard deletion cascades the preference and deletes these receipts even though the generic receipt table has no actor FK. Other operation receipts remain untouched. The trigger saturates the tombstone version at the integer maximum; it never prevents retirement through overflow. No deletion endpoint or account lifecycle authority is added.

Discovery's public GET city-hint returns Moscow/default with `Cache-Control: private, no-store`. No trusted ingress/local GeoIP is configured or activated in this candidate. It has no request-dependent lookup and ignores forwarded headers, peer address, coordinates and account preference; no provider, raw-IP storage, new IP logging, GPS request or consent effect. The additive response reserves source `ip` for a separately admitted trusted local implementation. Default fallback requires no infrastructure prerequisite.

Privacy/data flow: explicit client choice → authenticated own PUT → private preference plus scoped receipt (existing 24-hour receipt TTL) → authenticated own GET. Account preference has no automatic expiry. Neither value enters public projections, audit/outbox/analytics, profile city, Radar consent/presence or game-contact defaults. New code emits no preference/IP logs. Existing HTTP access logging/retention is outside this slice. All new responses prohibit storage; the hint additionally prohibits shared caching. Public profile and game DTOs are unchanged.

Alternatives rejected: profile reuse silently alters public location; implicit inference backfill fabricates manual choice; device-only storage loses account portability; remote GeoIP adds a privacy/network dependency; blind upsert loses concurrent edits. Client storage/precedence/SSR belongs to P1, whose acknowledged save must follow the server response.

Compatibility: OpenAPI 0.19.0 is additive to 0.18.0. Existing schemas/routes and stored profiles/games remain compatible; migration does not backfill. Generated Discovery DTOs extend the existing contracts `game-types` export/generator without package/lockfile changes. No transport SDK exists in packages/sdk at baseline, so this follows the established generated DTO practice rather than claiming a new full client. Independent QA verifies the source candidate before PM integration.

Recovery: revert candidate application/contract source before deployment, or retain the additive table/trigger for a later admitted rollback. Do not destroy saved choices or receipts through a down migration. This assignment only applied migrations to a newly initialized disposable task database, then stopped/deleted that resource. Live database/runtime untouched.
