## Design (decided; do not invent a different architecture)
1. `test_plan_gate.py` is a pure, stdlib-only, deterministic module with no network, no subprocess other than the read-only `git diff --raw` that testing/verify_profile.diff_changes already performs, and no model call. It NEVER executes candidate code or candidate tests (the controller must not run candidate payloads): the non-model runner stays a tool used by the author/QA/CI, the gate only checks the declared profile against the REAL changed files and injects short guidance.
2. Trusted-code binding: the gate loads tier_classifier/plan_block/verify_profile/catalog from a `testing` directory = `<gate dir>/testing` when present (installed layout), else `<gate dir>/../testing` (repo layout). Before importing it verifies sha256 of every file it uses against pins hard-coded in the gate module (and refuses `TESTING_PIN_MISMATCH` otherwise); sys.dont_write_bytecode, no candidate-worktree path is ever put on sys.path, the catalog/classifier are NEVER read from the candidate worktree. A repo test must assert the pins equal the real file hashes (so any later change of testing/* forces a conscious gate update).
3. Source of the plan: the TEST PLAN block is parsed (plan_block.parse) ONLY from the immutable admitted task acceptance text (`active['task']['acceptance']` or the equivalent field the controller already holds for the claimed task), never from candidate files, PR text, or model output. Missing/duplicate/invalid block => refusal code from plan_block (MISSING_TEST_PLAN, ...). The plan must also carry/require the independent-QA flag for T3.
4. Real-diff verification: at the exact head, run verify_profile logic on the real raw diff base..head (statuses, modes, renames, symlinks, deletes) and apply tier_classifier.verify_declared.
