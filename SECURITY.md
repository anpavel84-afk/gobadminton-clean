# Безопасность

Не помещать секреты, OAuth-токены, персональные данные, скриншоты чужих кабинетов или выгрузки БД в issues, PR, логи и документацию. Для сообщения об уязвимости использовать закрытый канал владельца репозитория; публичный адрес security-контакта ещё не назначен.

В сообщении нужны минимальный синтетический пример, затронутый commit/окружение и влияние. Не эксплуатировать production, не выгружать чужие данные, не проводить платежи.

При утечке: ограничить доступ → отозвать/ротировать секрет → оценить использование и затронутые данные → документировать восстановление. Удаление строки из текущего файла не удаляет её из истории Git.

Подробности: [модель безопасности](docs/security/SECURITY_AND_PRIVACY.md) и [deployment/recovery](docs/operations/DEPLOYMENT_AND_RECOVERY.md).
