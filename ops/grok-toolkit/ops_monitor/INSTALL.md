# OPS · Монитор (отдельная программа) — установка

Ничего из этого ещё **не установлено**. Папка `/workspace/outputs/ops_monitor_standalone/` — готовый комплект. Монитор не входит в репозиторий gobadminton-clean, не использует Issues/PR/исполнитель, не пишет в checkpoint и не трогает PROD, PLAN, VPN и старые сервисы Runner.

## Что это

- **Писатель снимка** (`opsmon/writer.py`, без LLM): раз в 30 с читает checkpoint (`state.json`, `parked.json`), квитанцию DEV и `systemctl --user show gobadminton-autonomy` **только на чтение** и пишет безопасный файл `/var/lib/gb-ops-monitor/snapshot.json`. Сам checkpoint, секреты, goal целиком, логи, GitHub — не читаются и не попадают в файл. Запускается от того же пользователя `__EXEC_USER__`, что и `gb-grok-status`.
- **Веб-служба** (`opsmon/server.py`, только stdlib Python): слушает `127.0.0.1:18090`, читает **только** `snapshot.json`. Вход по PIN, cookie-сессия 12 ч.
- **Страница** (`web/`): мобильная, 390/430 px без горизонтальной прокрутки, обновление раз в 30 с, ярлык на экран «Домой» (iPhone: Safari → Поделиться → На экран «Домой»).

## Адрес

**`https://dev.gobadminton.ru/ops-monitor/`** — самый нетронутый вариант: тот же домен и сертификат TLS, что уже работают, новый внешний порт не открывается, по образцу существующего `/runner-monitor/`. Ярлык на iPhone откроет именно этот адрес.

## Что нужно от root (ровно эти шаги; их делает `install.sh`)

Запуск: `sudo ./deploy/install.sh` (перед этим можно проверить без изменений: `DRY=1 ./deploy/install.sh`).

1. Создать системного пользователя `__MON_USER__` (без входа, без домашнего каталога) для веб-службы.
2. Создать каталоги: `/usr/local/lib/gb-ops-monitor` (код, владелец root), `/var/lib/gb-ops-monitor` (владелец `__EXEC_USER__`, 0755 — сюда пишет только писатель), `/etc/gb-ops-monitor` (root:__MON_USER__, 0750).
3. Скопировать код и страницу в `/usr/local/lib/gb-ops-monitor`.
4. Создать `/etc/gb-ops-monitor/config.json` (root:__MON_USER__, 0640): соль и scrypt-хеш PIN, секрет подписи cookie. PIN вводится скрыто в терминале при установке и нигде не сохраняется. **PIN вводит тот, кто ставит (Owner).**
5. Установить три unit-файла в `/etc/systemd/system/`: `gb-ops-monitor-web.service`, `gb-ops-monitor-writer.service` (User=__EXEC_USER__, `ProtectSystem=strict`, запись только в `/var/lib/gb-ops-monitor`, только AF_UNIX, без сети), `gb-ops-monitor-writer.timer` (30 с). Выполнить `systemctl daemon-reload`, включить таймер и веб-службу.
6. Nginx: файл `/etc/nginx/snippets/gobadminton-ops-monitor.conf` и **одна строка** `include …;` в `/etc/nginx/sites-available/dev.gobadminton.ru` перед `location / {` в блоке 443. Скрипт делает бэкап, `nginx -t`, при ошибке откатывает, затем `systemctl reload nginx`.
7. Скрипт проверяет: `healthz`, аноним без cookie получает 401, снимок появился.

Бэкап файла сайта nginx: `/root/gb-ops-monitor-backup-<дата>/` (путь также в `/root/.gb-ops-monitor-last-backup`).

Не нужно: открывать порты фаервола, новый домен/сертификат, `loginctl enable-linger`, менять Docker/compose/env админки, GitHub-токен, права на каталог исполнителя.

## Откат

`sudo ./deploy/uninstall.sh` — останавливает и удаляет службы и таймер, убирает строку include из nginx (с проверкой `nginx -t`), удаляет код. Дополнительно `--purge-config` (удалить хеш PIN) и `--purge-data` (снимки и журнал). Пользователь `__MON_USER__` остаётся (`userdel __MON_USER__` вручную). Мгновенно «выключить» без удаления: `sudo systemctl stop gb-ops-monitor-web` (страница даст 502, данные никому не отдаются). Исполнитель при этом не затрагивается вообще.

## Безопасность и честные ограничения

- **PIN из 4 цифр слабый сам по себе** (10 000 вариантов). Защита: 5 неверных попыток с одного IP → блок на 15 минут; общий лимит 30 неверных за час на всех → блок входа на 15 минут (минус: чужой может «забить» вход, но данных не получит; Owner заходит после паузы). Счётчики хранятся в памяти и сбрасываются при перезапуске службы, перезапускать её может только root. Данные монитора безвредные для постороннего (номера задач, этапы, короткие SHA), но выдаваться они всё равно не должны. Рекомендую 6 цифр: достаточно запустить `make_config.py` с другим PIN.
- Cookie: `HttpOnly; Secure; SameSite=Strict`, подпись HMAC, срок 12 ч, путь `/ops-monitor/`. Заголовки: `no-store`, CSP без inline-скриптов, `X-Frame-Options: DENY`, `noindex`. Вход принимается только как JSON с проверкой Origin (защита от подделки запросов).
- Только чтение: у веб-службы нет доступа к checkpoint; у писателя нет сети, он не вызывает GitHub и не запускает `autonomous_issues.py`; тесты проверяют, что состояние checkpoint не меняется.
- Адрес клиента берётся из `X-Real-IP` только от nginx на 127.0.0.1.

## Что показывает и чего НЕ показывает (честно)

| Блок | Источник | Первая версия |
|---|---|---|
| Сейчас выполняется | checkpoint | номер, название из строки `TASK id: …` в goal (иначе «Задача #N»), этап, попытка из 3, PR, коммит, QA, CI (счёт job, если есть в checkpoint), «замечено монитором» — время, когда писатель увидел смену состояния |
| Шкала | фаза | Задача → Код → PR → QA → CI → DEV → Принято; процентов нет; «технический план» не показывается (не применяется) |
| Исполнитель/модель | — | «не подтверждено» |
| На паузе / заблокировано | `blocked` + `parked.json` | причина, попытки, преемник, нужно ли действие Owner |
| Недавно завершено | журнал писателя | только то, что писатель увидел с момента установки; со ссылкой на квитанцию DEV; без квитанции — помечено «подтверждения релиза нет» |
| Следующие задачи | — | «очередь недоступна» (нужен токен GitHub на чтение или доступ к Issues) |
| Вне исполнителя (#53) | статическая запись | «ведётся вне исполнителя», без утверждений о работе агента |
| Свежесть | возраст снимка | старше 90 с — красная плашка «Нет свежих данных»; снимка нет — «нет снимка» |
