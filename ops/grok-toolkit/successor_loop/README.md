# Единый цикл «преемник» (successor_loop)

Как это работает, когда задача не дошла до DEV.

## Когда запускается
Задача провалила QA, исчерпала 3 попытки или припаркована.

## Шаги
1. **Сбор фактов** (`collect`). Скрипт сам берёт:
   - текст старой задачи;
   - отчёты QA всех попыток (файлы исполнителя `qa-<номер>-a<попытка>.json`; их читаю через Desktop Commander, только чтение);
   - падения автотестов CI по каждой попытке, с точным текстом ошибки;
   - ваши служебные комментарии (возобновление, парковка) и список файлов PR.
2. **Технический PM** (`pm`) — Кодекс старшей модели (gpt-6.1-sol, high) на сервере, через уже установленный `codex-review`.
   Он читает реальный код, находит причину каждого провала и пишет текст новой задачи.
   В тексте обязателен раздел **«Замечания QA предыдущих попыток»**: по пункту на каждую попытку —
   «что нашла QA/CI → как это учтено» или «вне задачи: почему».
3. **Независимый ревьюер** (`review`) — отдельный запуск Кодекса через тот же `codex-review`, с чистого листа.
   Ревьюер другой семьи моделей (Antigravity / Gemini) подключается через `--reviewer cmd:...`, но сейчас
   **отключён**: по вашему handoff от 19.10 модельные CLI от __EXEC_USER__ не запускаю и AGY не использую как
   проверку, пока не исправлены его дефекты (нужны отдельные тесты и ваше «да»).
   Ревьюер получает текст + все замечания QA и проверяет, что каждое закрыто. Если «нельзя» — берётся его
   исправленный текст и проверяется ещё один раз (не больше).
4. **Проверки** (`lint`): мой линтер, проверка формата исполнителя, жёсткие лимиты (размер, 3 попытки,
   запрещённые пути, никаких шагов с сетью и условий «остановись») и проверка, что ни одна попытка не забыта.
5. **Публикация** (`publish`) — только по явному флагу `--publish`: Issue от вашего имени, русское описание
   в мониторе, слежу, когда исполнитель возьмёт задачу. Без флага цикл останавливается перед публикацией.

## Команды (для меня)
```
~/sshvenv/bin/python successor_loop.py all 96 --pr 97 --qa-dir evidence/96          # всё, кроме публикации
~/sshvenv/bin/python successor_loop.py review 96                                     # ревью черновика (Кодекс)
~/sshvenv/bin/python successor_loop.py compare 96 --body ФАЙЛ                         # что из QA не учтено
~/sshvenv/bin/python successor_loop.py publish 96 --title ... --title-ru ... --meaning-ru ... --publish
```
Ревьюер: `--reviewer codex` (по умолчанию) | `cmd:/путь` (любой внешний ревьюер:
получает файл тела и файл фактов QA, печатает вердикт и исправленный текст в том же формате). `agy` — отключён.

## Что не делает
Не трогает PROD, состояние исполнителя, чужие Issue; не печатает токены; ничего не публикует без `--publish`.
Команда root для этого цикла не нужна.
