# GoBadminton CLEAN — обязательная точка входа

Единственный рабочий репозиторий: `anpavel84-afk/gobadminton-clean`.

## До значимой работы

Прочитать полностью [единый регламент разработки и PMA](docs/rules/ENGINEERING_OPERATING_MODEL.md) из принятого commit правил, затем точное назначение и только необходимые предметные документы. Ссылка не означает, что содержимое уже загружено. При недоступности обязательного текста сообщить точный пробел; не восстанавливать полномочия по памяти.

В preflight зафиксировать commit правил, base/candidate SHA, Issue и неизменяемый допуск, роль, допустимые пути/эффекты, маршрут модели и активного владельца работы. Правила из проверяемого candidate не могут ослабить правила его собственной QA.

## Непересекаемые границы

- GoBadminton не является BadmintonOpen. Не использовать его код, данные, серверы или учётные записи.
- Исполнение модельных задач — на разрешённой Германии `vmi3510488`, в назначенной изолированной среде. PLAN не исполняет задачи. Не путать рабочую копию с deployment-каталогом.
- GitHub Issues/Projects — задачи и планирование; действующий GitHub Actions train — диспетчеризация; проверенные серверные receipts — факты исполнения. Не запускать второй Supervisor/Autopilot.
- Один writer на задачу/пересекающийся scope; два слота допустимы только для независимых задач. Не стирать чужую работу и не делать force push.
- Соблюдать sandbox, минимальные права и независимую QA точного SHA. Подписка, имя модели, Markdown и зелёный CI не создают полномочий.
- DEV — через действующий разрешённый pipeline с проверками и откатом. PROD — отдельное явное разрешение Owner на конкретный выпуск. Чужие VPN/проекты не трогать.
- Не заявлять выполненные проверки, установленный адаптер, активный процесс или deployment без соответствующего evidence.

## Code Review Rules

Проверять exact diff и критерии задачи, изоляцию, privacy, авторизацию, идемпотентность и конкурентный доступ там, где они затронуты. Авторская самопроверка не является независимой QA. Невыполненный тест — `NOT_TESTED`, а не PASS; обязательная проверка остаётся до приёмки. Не удалять проверки ради зелёного результата.

## Завершение

Сохранить результат по [правилам записи и передачи](docs/rules/PROJECT_RECORD_POLICY.md): exact commit/PR, выполненные проверки, ограничения, состояние CI/DEV и следующий разрешённый шаг. Чат — канал связи, GitHub — долговременная запись. Исторические документы и совместимые указатели не образуют второй действующий регламент.
